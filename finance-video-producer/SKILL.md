# 金融视频制片 v2.4.2（主用合并版）

本包是普通 finance video／金融视频制作的主用入口，沿用 v2.4.1 连贯分段投模、v2.4.0 发音定点返修、真实素材路由与媒体交付修正；v2.4.2 将具体消耗预估改为可选信息，取消本包附加的预估失败挂起门槛，保留高消耗提醒和本批实际生成确认。独立试用包 finance-video-producer-v2-4-0-pronunciation 仍保留，仅在用户明确指定独立试用包时使用。升级技能文件不自动迁移或重建旧项目数据库、不重生成已采用片段；旧项目继续时先查在途回执、展示 skill-diff，并按用户明确采用范围执行。

由当前 Agent 负责对话和调度。本包只需安装一次。资料中形如 video-scene 的名称均对应包内 references 下的同名目录，读取其中的 guide.md 即可。按当前任务读取，不启动一串子 Agent，不逐项向用户回报后台分工。

## 每段开拍前的交付

轮到某段时执行 `segment-text 段号`，把返回的《素材与提示词确认单》全文直接发在用户对话正文，其中包含投模词全文、真实素材、入口、声音、秒数与版本。实际发出后登记 `present_segment` 的完整正文和消息标识，然后结束本轮等待用户回复。收到针对这张单的后续回复，才记录 `approve_segment`；再完成高消耗提醒与宿主本批实际生成确认，才能 `claim-video`。每段首次、整段返修重投和同稿重抽都执行这一轮。方案通过、素材采用或上段通过后，下一动作是交付待拍段提示词。恢复时先查交付记录和在途回执。

用户说“指定位置没改对”时，先读 [局部返修](references/video-finish/repair.md)，对照原视频定位到具体时段和区域，明确验收标准，再选择真实支持的编辑入口。局部编辑使用独立 `repair_plan` 与 `claim-repair`，交付本次完整编辑指令。整段重生成使用原有 `retry_clip`，确认单标明整段画面和声音可能重新变化。

用户指出台词读错时，读 [定点发音返修](references/video-finish/pronunciation.md)。定位片段、原句与正确读音，再给用户两个选项：① 用 Seedance 生成修音候选并把声音拼回原片，② 导入修好的短音频并拼回原片。用户已经指定方式时直接准备该方式的输入，无需重新选择。两种方式都保留原画面，回听查验后再采用候选。未选择时等待回复。

## 开拍前：消耗预估与真实素材

逐段内容确认不替代宿主要求的本批实际生成确认。首次、重生成、失败重试及修音候选均按 [开拍前检查与失败分支](references/video-workflow/references/host.md#开拍前检查与失败分支) 执行：展示真实参数，提示视频生成为高消耗生成，取得本次明确确认。具体消耗预估仅作可选信息；只有付费提醒、预估不可用、计算失败或缺数值时如实说明，不单独挂起、不编造数值或填 0，不静默反复查询。

本包不要求额外的“允许无预估生成”确认，也不自行把具体消耗值或额度类型设成必填。真实输入、权限、当前批次确认及宿主/工具当时明确要求的前提仍须满足；不得仅凭本包历史描述宣称平台禁止无预估生成。旧预估卡点在继续原项目时按记录核对并恢复，不自动改旧项目或绕过其他实际限制。

参考视频、参考图、样音不是三项必填。按本段真实输入选入口：只有文字用文生视频，只有图片用图生视频；有样音而没有视频时，核实并使用支持图片＋音频的媒体生成入口，视频列表按实际 schema 留空或省略。不得为凑输入生成占位视频、擅自搜索无关视频或丢弃已采用样音。真正需要原片的编辑/修音仍须绑定原片。具体见 [参考资产包](references/video-references/guide.md#角色样音与视频素材)。

## 对话就是轻量工作台（状态层 v2.4.2）

首次执行前读取 [总控](references/video-workflow/guide.md)、[状态事件](references/video-workflow/references/events.md) 和 [宿主接法](references/video-workflow/references/host.md)。有本地 Python/文件能力时，必须使用随包 `workflow.py` 和每个项目的独立 `workflow.sqlite`；不可只靠聊天记忆或普通 Todo 清单声称可恢复。原有八个细节点对应四个对外阶段。第 03 步按待生成段循环交付和确认，第 04 步按实际样片循环审看。

### 首次使用：环境自检（随包自带）

开拍前先跑内置自检，核对本地运行时与技能完整性；缺项按报告提示处理，可选依赖经确认后安装：

```bash
# 只检查（不改动环境）；env-check 不要求项目数据库存在
python3 references/video-workflow/scripts/workflow.py <db> env-check
# 经确认安装可选依赖 edge-tts；ffmpeg/ffprobe 属系统级，脚本只给命令不代提权
python3 references/video-workflow/scripts/workflow.py <db> env-check --install
# 也可直接运行独立脚本
python3 references/video-workflow/scripts/env_check.py --install
```

- 必需本地项：Python 3.8+、标准库；ffmpeg/ffprobe 仅在本地抽帧、探测、拼接整片时需要，单段出片与台账不依赖。
- 可选本地项：edge-tts（样音锚定路线生成角色样音；也可用会话内音频工具或自备样音替代）。
- 豆包侧生成/交付能力（image_gen、image_edit、text_to_video、image_to_video、media_to_video、video_token_compute、FileBatchUpload，以及文件交付能力）由宿主会话挂载，脚本只列按需能力，须在会话内核对真实注册和 schema。`media_to_video` 可按实际能力接收图片＋样音而无视频，不是每段必需入口；视频／图片按宿主媒体卡交付。


每次继续先读取状态；开始节点、保存产物、等待用户确认、工具返回、出错或暂停时先登记，再运行 `status-card`，将实际摘要显示在对话中。固定显示项目名、记录版本、当前节点、各节点状态、中间产物、卡点/在途任务及下一步。图/视频仍使用宿主媒体卡，文件仍用宿主交付工具，状态卡不能冒充可点击界面或媒体交付。历史消息不原地刷新，不声称无会话时后台持续运行。

执行节点前用 `node_start`；失败用 `node_failed`，保留原因。保存文本产物后用 `register_artifact` 登记真实路径、摘要和来源环境；不要覆盖已登记旧版本文件。用户说“查看 N04 产物”时读 `artifact N04` 并交付当前分镜。用户说“暂停/继续”时提交相应事件；暂停阻止新工作，但原远端任务可能仍运行，继续时先查询它。

实际生成/合成前必须用 `claim-video`、`claim-image`、`claim-audio`、`claim-repair` 或 `claim-compose` 原子领取一次，再使用返回的已授权请求调用真实工具，立即回写 `job_update`。只读 `media-request` 是预览，不允许据它直接提交。超时/回执丢失标记提交结果不明，只查询原任务；不得重复抽卡。具体调用仍先满足宿主的视频/图像 Skill 与确认规则。

使用者可编辑各编导、故事、分镜、投模词的 `guide.md`。发现文件变化，展示 `skill-diff`，让用户决定“仅用于后续”或“从某节点重跑”；记录采用版本再执行。只修某段沿用原来的依赖失效与缓存复用，未受影响的独立段保留。不要为方便改掉状态机、版本校验和提交去重保护。

## 一轮给出可决定的方案

用户只说 idea 时，先确定观众看完要看懂什么，锁住原句、片长、指定的产品与真实素材。判断是否确实缺影响成片的信息。可推断的机位、色调与节奏直接采用可改建议；只有拍法或事实会发生实质变化才追问。简单纯文字短片可在这轮直接给方案。完整规则见 [入口判断](references/video-intake/guide.md) 和 [总控](references/video-workflow/guide.md)。

同一片选一个主编导。观众跟随人物的遭遇或关系用 [情景编导](references/video-scene/guide.md)；主要听出镜人讲明白用 [口播编导](references/video-presenter/guide.md)；靠图解或界面顺序学会用 [图解编导](references/video-explainer/guide.md)；活动揭晓和参与入口推动节奏用 [活动编导](references/video-campaign/guide.md)；重点看产品外形、材质或一次演示用 [展示编导](references/video-showcase/guide.md)。在反诈剧情里，屏幕上的骗子说话仍属于男主故事中的一个声源。

将 [故事](references/video-story/guide.md)、[文案审查](references/video-copy-review/guide.md)、[分镜](references/video-board/guide.md)、[投模词](references/video-prompt/guide.md) 的适用工作合并成同一次答复。一张短表给每段的秒数、动作、发声者/逐字台词、画面字、拟用素材和接法。用户可直接改原句与最终提示词；有资金收益等表述时检查归属、上下文和警示。先把待核项说清，再请用户确认。已成熟且被采用的原文按需原样保留。单一无词动作只写决定成败的起点、接触、末态和声音。只有对白、产品细节、UI 步骤或接缝需要时才展开时间锚点。

## 首稿交付前（R3）

按 [整片编写与逐段投模](references/video-prompt/guide.md) 先完成整片分镜，再逐段输出可独立提交的正文。对读所有相邻段的末态与首态，注明经确认的有意变化。同镜头或连续动作跨段时接真实有效尾帧。精确动作秒点按需进入模型正文，后期旁白和段间剪辑随各自的制作清单交付。

先读 [创作验收](references/creative-review.md)，按当前主拍法和当前交付物核对可执行证据，不把导演稿自检说成真实成片验收。逐字要求写入 `brief.exact_copy`；音画同文的 caption 引用同一 `line_id`，原句的空格、数字和句末标点都不补写。静音与无台词分开记录，指定的最短窗口使用 `min_duration_ms`。

`plan` 成功后可用 `draft-export --output 新版本.md` 导出未采用草案；它与 `plan-card` 同源、只读、不增加修订号，也不授权生成。正式 `export` 仍要求已定稿。需要完整投模词时直接使用导出的实际全文，创作理由另写，不能把解释或表演停顿塞进文字轨。达到用户本轮指定交付物就结束，不自动出图或继续开拍。

进度查询、数据库快照和回执说明从现有版本读取；相同 `brief` 重送不改变修订号或撤销采用。`summary` 兼容命令映射到原适配的 `status-card`，不另建第二套状态控制。执行和交付同时遵循 [豆包接法](references/video-workflow/references/host.md)。

## 四步确认与交付

统一使用 [四步交付与台词时长](references/四步交付与台词时长.md) 的名称。每轮展示到用户能决定下一步的程度。

1. **《需求确认单》**。用户给目标总时长，Agent 给预计无词秒数、可说时间、已有或拟写字数、时长判断，以及建议分几段、每段内容、起止和切点理由。普通话自然偏快按每分钟可说时间约 250 字（240–270）初排。只有 idea 时给预算；完整稿给实数字数与冲突取舍。
2. **《分镜脚本确认单》**。沿已定段界列镜头、动作、谁在几点说哪句、画面字、接缝与所需图／音。检出过挤话轮；改段界说明具体原因。材料齐可同轮呈现 01 和 02。方案通过后准备参考资产。
3. **《素材与提示词确认单》**。先通过 [参考资产包的生成](references/video-references/guide.md) 交可看、可听的候选并选版本。每个出声人物一份样音，后续只绑定本段说话人。轮到某段首次提交或返修重投时，运行 `segment-text 段号`，在对话正文交付返回的完整确认单，逐字贴出本次全文、实际输入及顺序、入口／模型、画幅、时长、声音与返修差异。实际交付后用 `present_segment` 记录全文和消息标识，结束该轮。用户后续针对本段本次的回复绑定这条交付记录，记录 `approve_segment` 后，仍须完成高消耗提醒与宿主本批实际生成确认，再原子 `claim-video`。具体预估不作额外门槛。同稿重抽重新展示并确认；`start_batch` 只准备待拍清单。依赖上一段时先取已采用的真实有效末帧。独立段也各自走此流程。仅导出在此交稿。
4. **《分段样片确认单》**。按 [成片审查](references/video-finish/guide.md) 交可播放的确切版本、实看实听结果和问题秒点。指定返修先定位时段、区域及目标，局部编辑验收通过后采用新版本；有效末帧改变时再复核依赖段。全部采用并取得合成同意后，交《成片交付包》，含实际成片、逐段实发全文、资产映射和验收记录。“采用这些段并合成”可一次办妥两项。

同一工作任务内保存版本、用户原话和素材/片段映射。使用 [状态执行器](references/video-workflow/scripts/workflow.py) 与 [事件说明](references/video-workflow/references/events.md)，不另建网站或服务器。没有代码/持久化能力时明确当前只能提供可保存的文本记录，不能声称自动恢复、原子去重或状态门禁已生效。旧项目缺少任务台账时先核对原任务，不能因为数据库没有回执就直接重新生成。工具字段、可用额度和回执按宿主实际返回，参见 [宿主能力约定](references/video-workflow/references/host.md)。
