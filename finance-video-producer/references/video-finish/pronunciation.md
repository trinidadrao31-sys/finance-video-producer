# 定点发音返修

适用于成片或样片把正式原句里的字词念错。对照已锁定原句和实际人声，从前一句尾音听到后一句起音。登记原片版本、段号、段内起止毫秒、说话人、台词 ID、词、实际读音及正确读音。用户给整片秒点时，按实际剪辑时间线换算并保留两种时间。ASR 用于找位置，正确与否以实听为准。若正式台词本身要变，先回分镜脚本改母稿；口型错位、漏词、画面问题按各自的局部返修流程处理。

## 用户选方式

交付可回听的时间窗、原句、正确读法和两种方式。给出当前方式是否可执行及具体缺项，等待用户选择。用户已经明确选定时接着收齐该路线的输入。

1. **用 Seedance 生成后回拼。** 以覆盖目标短语和前后发声的原片段为输入，让 Seedance 生成带正确读音的候选视频。先回听生成结果，定位候选内真正可用的声音区间，再只取这段声音拼回原片。
2. **导入音频后回拼。** 请用户提供读好的短语或短句音频。可从用户音频中截取指定区间，先试听内容，核对说话人、有效时长及前后衔接，再拼到原片的指定位置。

示例：「S03 段内 1.20–2.05 秒，『遥墙机场』的『墙』应读 qiáng。请选择 ① 用 Seedance 生成后回拼，或 ② 发我一段已读准的音频，我帮你拼回。两种都保留原画面。」对哪一处、正确读法或导入文件有歧义时，只问影响操作的那一项。

## 执行和复核

- 两条路线都先核实可读的原片及局部回拼能力。若为可见对白，选能贴合原口型的替换区间，优先保留发声起止和换气。必要时用小范围变速适配，然后回听。完成回拼后复核读音、说话人、语速、画面同步、区间两端和片长。有独立人声轨时优先修该轨并保留底轨；原片只有混音时说明补丁区间的背景声可能随替换改变。
- Seedance 路线先发现实际工具、模型 ID、源视频输入和带声编辑能力。以 Seedance 2.5 的方舟接口为例，编辑请求用 `omni_reference_task_type=edit`、`reference_video`、`ratio=adaptive`、`duration=-1`，参考视频为 4–30 秒。按当前宿主的真实 schema 映射。短词仍使用符合入口时长的源片范围。提示词秒点按所提交参考视频的局部时间换算。需听生成候选的实际音轨，候选语速、时点或口型可能偏离。提供的候选音频不合格时保留原片，让用户决定重试或换方式。参见 [Seedance 2.5 接口说明](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)。
- 导入路线仅消费用户选择的实际音频。先探测或截取有效发声范围。用户允许的范围内做对齐和渐变。当输入与原口型明显不匹配时保留原片并提供具体重录范围。
- 正式声音如果在后期旁白轨，使用当前片段实际采用的旁白轨作回拼底稿。Seedance 如需参考画面，先用已核实的剪辑能力制带该旁白的临时片，候选仅供取声。用支持独立音轨的后期工具回拼，回听后按原流程登记新的 `post_track`，用当前样片任务号重新确认合成清单。包内回拼脚本处理有原声的原视频。
- 交付原片和修复候选供回听及对比。试听未通过时保留原片和待处理状态。用户采用后更新本段选片及合成清单。画面流校验相同时沿用原有效末帧资产。

缺少生成或回拼能力时，明确缺口并停在当前已选路线。使用另一条路线以用户选择为准。按本次沿用的确认单展示实际请求与可能消耗，取得确认后调用。避免为找一处声音重生成整片。

## 状态执行器

本节用于有状态的原片声音返修。选择后提交 `repair_plan`。沿用 [局部返修](repair.md) 字段，`method=audio_edit`，并带下列字段。如果用户选了导入音频但尚未上传，先等待真实文件。

| 字段 | 值 |
|---|---|
| `pronunciation` | `cue_id`、`term`、`observed`、`expected`。词须在已锁定原句，台词和范围须相交。 |
| `pronunciation_route` | `seedance` 或 `import_audio`。外层 `user_message` 保存用户选定路线的原话。 |
| `execution` | 实际后期工具配置，`controls` 包含 `source_video`、`time_range`、`audio_edit`、`audio_splice`。独立层沿用分轨要求。可见对白用 `mouth_plan=existing_timing`。 |
| `seedance` | 仅路线 1 提供。含 `tool`、`model`、`schema_evidence`、`verified=true`、`controls=[video_edit, reference_video, generate_audio]`、真实入口时长 `min_ms` / `max_ms` 和 `source`。 `source` 含实际参考片 `uri`、`sha256` 和它在原段内的 `from_ms` / `to_ms`。 |
| `replacement` | 路线 2 在计划中提供。含 `uri`、`sha256`、`media_type=audio`，以及从导入音频实际开头算起的 `from_ms`、`to_ms`。项目段内回拼范围仍取顶层 `from_ms` / `to_ms`。 |

1. 用 `repair-text 段号` 交付定位与完整执行输入，登记 `present_repair` 和用户后续的 `approve_repair`。
2. 路线 1 执行 `claim-repair-source 段号 --expected REV`，按领取的请求生成一次，并用 `job_update` 跟踪真实回执。得到可用声音后用 `repair_patch` 登记 `id`、本次 Seedance 的 `task_id` 和 `replacement`。其 `media_type=video`，`uri` 取同一成功回执的候选视频，附 `sha256`、视频内实际声音区间 `from_ms` / `to_ms` 和回听 `evidence`。
3. 两条路线都用 `claim-repair 段号 --expected REV` 领取回拼，保存返回的 JSON。下方命令中的路径都换成任务中真实可读取的输入和新输出。

   ```bash
   python3 references/video-finish/scripts/splice_audio.py claim.json source.mp4 patch.wav repaired.mp4
   ```

   补丁也可以是路线 1 返回的候选 MP4/MOV。脚本依据领取请求的摘要和时间窗，调用 FFmpeg/ffprobe，只替换指定 PCM 区间，区间内短渐变并验证视频流 SHA-256。它支持接近零时点的一条原视频/原音轨，以及单或双声道的原声音轨。偏移、多轨或已分离人声按实际能力使用其他已核实的后期工具。AAC 回写会重新编码音轨，区间外的编码字节可能变化。
4. 由实际回拼任务登记 `job_update` 成功后，提交 `repair_result`。本地执行以领取的 key 对应独立运行目录，保存本地执行 ID、脚本结果及实际产物路径。额外给 `audio_splice` 为脚本输出的 JSON 或等价的真实核对结果，`duration_ms` 取候选实际时长，`ending_changed=false`。使用原帧和末帧资产。既有 `qa`、`checks` 与用户采用规则继续适用。候选生成回执和回拼回执分别记录。回拼失败时先排查已有补丁和输出。需要改变已领取的计划或音频来源时，待在途任务查清后取消该轮，展示新的计划。
