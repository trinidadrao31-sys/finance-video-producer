# 宿主能力约定

部署者在会话开始时声明实际可用的工具与字段。以下英文标识用于说明输入输出；客户可使用任意工具名、HTTP 服务、工作流节点或人工回传。按实际接口做字段映射。文件夹名只标识要读取的编导指令；不支持按名称加载的宿主直接执行上下文内的同名章节。

|能力|传入|取得的实际结果|
|---|---|---|
|呈现与回应 present / user_reply|项目、对象 ID、当前版本、全文或可查看的真实图片/片段、要用户决定什么|原始用户消息或消息 ID，连同本轮已展示的对象及版本保存。文本、文件附件或可预览链接皆可|
|读取与提交状态 load_state / commit_event|项目 ID；写入另带 expected 版本号、事件和确认依据|当前版本和状态，或版本冲突。对同一项目原子写入；恢复时读取已提交记录|
|生成参考图 generate_image / edit_image|ref_id、spec_hash、完整生图提示词、画幅；编辑另带真实底图和要保持的特征|任务回执、可查看的实际图、可再次取用的资产版本与内容摘要。上传已有图时直接登记其来源|
|生成视频 generate_video|当前授权的段 ID、完整 prompt、画幅、请求秒数、有序媒体及各自用途、音频要求；记录有效毫秒数供剪辑|真实任务 ID；完成后返回可读取的视频。媒体角色含 reference_image、reference_audio、reference_video、first_frame，按模型支持的方式提交|
|查询任务 get_result|首次提交的任务号|等待中、已成功及资产、或失败原因。提交超时先查已有记录；如既无任务号也查不到去重键，标为提交结果待核|
|读取媒体 probe_media / extract_frame|实际视频、有效区间、抽取时刻|时长、画幅、音轨，以及该有效区间的第一帧、末帧和资产版本|
|审看与回听 inspect_media / transcribe|实际候选图或视频、时间码、对应故事/台词/分镜|可定位的画面观察、逐字实听或转写和音画时序证据。仅能转文字时，口型仍待审看|
|裁剪拼接 assemble|按序列出的已选片段、各自有效区间、接缝、音轨计划|真实成片、实际时长。回到审看与回听检查整片|

**如何接一个不同名字的工具。** 若部署者提供的图像工具实际叫 make_asset(description, aspect, source)，将当前图的 prompt 传给 description，ratio 传给 aspect。文生图按真实接口省略 source；编辑时把所选底图解析成工具可读的实际输入。将工具返回的 job 编号登记为 receipt，取回可打开的图给用户看。只有用户对该候选的回复才可随当前素材卡登记选图结果。对未知的名称、参数和素材格式，先读取宿主提供的能力说明。

**保存和继续。** 在已授权项目目录记录当前步骤、对象版本、已确认内容、待补件、所选资产与已提交任务。有本地执行能力必须使用 workflow.py；每轮加载 DB，不把聊天摘要当成权威状态。更改已展示对象须重新展示并确认，旧确认不能放行新版。候选媒体摘要取实际字节 SHA-256。每次恢复读取 status/dispatch 并显示 status-card；若数据库/文件在另一个环境，先回到其来源环境或经授权转移，不能默默重建空项目。

**提交与网络故障。** 使用 claim-* 原子领取输入；领取结果保存后，当前执行最多调用一次远端。任务号、成功文件、错误和进度均从实际工具回写。若领取后执行中断且无法查清是否提交，保守按 submission_unknown 处理，不直接重试。取消先记 cancel_requested，等真实服务确认才记 cancelled。本地门禁防止重复放行，不保证远端网络“恰好一次”；服务不支持去重查询时必须停在待核，不绕过门禁。暂停仅停后续动作，不自动取消已提交任务；没有后台服务时不会在会话结束后自行轮询。

**用户可改的范围。** 编导、文案、分镜、提示词 guide.md 可自行调整。改动后先显示 skill-diff 并记录采用范围。底层 Python 事件合同、事务、版本和去重规则属于控制层，不作为日常创作参数；修改它们必须重新跑随包 test_workflow.py。未来采用只影响以后新生成的产物，旧任务仍保存原输入与原规则版本；重跑按指定节点失效下游，保留全部历史。

**提示词上屏与确认凭据。** segment-text 或 repair-text 返回的正文先通过对话文本实际交付给用户，再登记 present_segment 或 present_repair。工具内部返回、文件落盘和进度摘要都应另行记录用途。优先使用真实消息 ID；宿主不提供 ID 时保存可回溯的对话顺序号、完整正文及用户后续原话。结束交付轮后再读取用户回复，执行器校验已登记的消息关系。实际消息是否上屏须由宿主确认。只读查询任务结果继续用原任务回执。

同镜头续接的 `first_frame` 媒体必须映射到宿主真正用来锁定首帧的字段。若工具仅支持普通参考图，先核实其他入口或重新确认接法。新编方案合成时，按清单 `seams` 处理段界，复核相邻两张有效帧和实际前后画面。工具字段依真实 schema 映射。

**发音返修。** Seedance 候选使用 `claim-repair-source`，局部换音使用 `claim-repair`。分别登记真实任务回执。前者只提供取声素材。后者须输出复制原视频流的新片，可用包内 `splice_audio.py` 或效果经核实的宿主后期工具。见 [两条发音路线](../../video-finish/pronunciation.md)。

**对话展示。** 将 status-card 输出作为固定状态区，不把内部项目 ID、远端任务句柄、客户身份等直接展示。本地文件路径只作为产物定位，使用宿主交付工具提供可打开文件；图像/视频用宿主媒体卡。固定消息是快照，不是可点击按钮或实时更新的网页。

**豆包中的模型和媒体交付。** 外部模型调用先读取当前安装的视频 Skill；用户指定模型时，还需读取对应模型 Skill 并用真实 schema 映射，不把提示词里的名字当作已设置模型。若宿主要求指定模型的 Prompt 全文逐字透传，把用户确认的原话全文保存在实际请求中，不自动补行内同义词、标点或删句。用户只授权分镜/提示词、仅导出或某段返修时，不扩展为整片生成、自动采用或无限重抽。

实际视频结果成功后立即通过宿主 RichMediaCard 交付真实视频，图片同样用媒体卡；音频、文档等非图片视频产物使用 present_files。状态卡、路径文本、截图或成功描述不代替本体交付。按本次已授权审查任务保存本体并记录实际视听证据，不扣留成功候选；记录实际尺寸、帧率和有效时长，不用设计规格冒充实际媒体参数。工具要求 URL 而只有本地素材时先使用当前宿主上传能力，不把本地路径直接当 URL。

**只提供对话的宿主。** 按本轮材料完成补件、故事、分镜与提示词，方案、实际选图与选片需要确认时结束回合，等用户回复。以“项目、阶段、版本、确认原话、所选素材、下一步”给出可复制的进度记录，跨会话可由用户带回并核对原文。不能解析的文件只登记为待取得。若项目需要制图但未绑定图像工具，交付生图提示词，等用户在外部出图并回传可审看的候选；也可按用户选择返回故事或取消该图项。没有媒体执行或审看能力时，只交付已完成的文本、素材清单及待办。不能从模型文字、演示数据或看过提示词推定已看过、已生成、已确认成片。

## 开拍前检查与失败分支

**先区分真实素材。** `media_to_video` 不是视频、图片、音频三项必填。当前豆包素材路由支持“音频作为输入，无视频，可同时有图片”；实际 schema 与模型能力仍须核实。只有本次真实输入的视频才填视频列表；没有视频时按 schema 传空数组或省略，不制造素材或把分析样片自动转成生成参考。只有图片、没有必需音频时走 image_to_video；只有文字时走 text_to_video。`execution.media_roles` 表示可接收用途，所需素材由本段实际内容决定。

**消耗预估是可选信息，不是本包附加的执行门槛。** 内容确认与实际生成确认仍分开；生成前须展示本批参数并提示“视频生成为高消耗生成”，取得宿主要求的本次明确确认。以下适用于新生成、重抽、失败重试、生成式编辑和修音候选；纯导出、查询原任务和本地技术回拼不新增生成确认。

1. 本包不默认要求调用 `video_token_compute`。用户要求估算或实际宿主要求查询时，在本批真实参数就绪后查询一次。按原文保留返回信息：有具体数值则如实展示；只有付费提醒就展示提醒；不可用、失败或没有数值则明确“本次未取得具体消耗预估”。不得编造数值、填 0、推断额度不足或静默反复请求。
2. 预估缺失、计算失败或额度类型未知不单独登记 `node_failed N06`，不要求用户额外选择“允许无预估生成”。保留已取得的真实提醒，按正常的本批生成确认继续；成本提示不能替代用户明确授权。本地执行器不检查具体消耗值或额度类型，也不证明额度充足。
3. 真实输入不支持、必要生成参数缺失、用户未确认或拒绝、实际权限/额度限制、宿主当时明确要求且尚未满足的前提，仍须停止相应提交。将真实卡点及未提交/提交不明状态写入 `node_failed N06`，说明恢复条件；已有任务仅按原回执查询。不能把估算失败误写为视频服务失败。
4. 旧项目若仅因预估缺失挂起，继续时查原状态和在途回执，展示规则差异并登记采用；不重建数据库或重做已选素材。真实输入及本批生成确认就绪后，登记 `node_start N06`，注明已取消本包的预估硬门槛和真实确认依据，再正常 `claim-video`／`claim-repair-source`，调用一次并回写 `job_update`。若还有其他真实卡点则保持挂起；不按文字关键词自动解除旧失败记录。
5. 宿主或真实工具当时有明确的强制前提时仍按其要求执行，但必须给出实际依据，不能仅凭本包旧文案断言“平台禁止无预估生成”。不修改内置技能、权限检查或远端服务限制。参数或输入有实质变化时重发当前全文并重新确认；旧授权不外推到重抽、后段或新增任务。

## 按当前阶段核对能力

运行 `scripts/workflow.py 项目数据库 env-check` 可检查当前机器的相关能力；在宿主会话另行查看当下挂载的真实工具及字段。仅用到本地拼接时才依赖本地 ffmpeg／ffprobe，声音可走已开放 TTS 或用户提供的资产。缺项说明具体影响，用户选择可行入口或确认安装。记录已核实、缺失或待核。每段提交前重核工具、模型、媒体角色、文件形式、音频开关与限制。实际 schema 或支持范围变化时更新 execution 及确认卡，重新展示。宿主限额若为 15 秒，按本段各样音实测总时长核对；其他入口采用各自限制。

人物现场普通话优先走支持角色图、对应样音与正式词音画同生的入口。豆包那次同改了样音、提示词和机位，现有证据只验证了那次组合。画面直出、带参考音频都可能出现错语言或换声。相同路线失败先定位具体原因，再让用户决定修订后的输入。工具不接音频时展示缺失的参考和替代拍法，重新取得确认；不要丢掉声音输入照投。后期旁白适合画外声或产品演示，实际成片检查配音及时间轴。
